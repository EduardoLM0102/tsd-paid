## 2026-09-07 — full Google Ads + GTM + GA4 tracking audit (read-only, no live changes)

Triggered by Edu asking why nonbranded Search shows 0 conversions and whether GA4 disagrees. Full detail in `topserv-workspace/clients/cs-air/google-ads-log.md`. Headline findings:

- **GA4 does NOT show hidden nonbranded conversions.** Its `contact_us`/`apply_for_financing` events are page-view-triggered, not form-submit — the real submit event (`generate_lead`) fired 0 times from nonbranded in 30d. Only real uncounted signal: 4 `phone_click` taps, confirmed (not an undercount) by cross-checking landing pages against the big unattributed `(referral)`/`(not set)` google/cpc bucket in GA4, which turned out to belong to the Smart Campaign (lands on homepage), not nonbranded.
- **Root cause is account-wide, not nonbranded-specific: CallRail's Google Ads integration is dead.** Conversion actions `First Time Phone Call` / `Repeat Phone Call` (CallRail's standard default naming) are ENABLED but show 0 conversions for 30+ days across the WHOLE account, despite GA4 logging 181-604 real `phone_call` events (30d/90d) that don't trace to any tag in the GTM container — almost certainly CallRail pushing to GA4 directly, bypassing Ads entirely. This is the single biggest lever in the account: every campaign is missing website-originated call conversions, not just nonbranded.
- GA4 property `310229049` has **zero Google Ads link** (confirmed via Admin API) — no gclid campaign-name resolution, no conversion-import backup path.
- Account-level `tracking_url_template` (`utm_campaign={campaignid}` etc.) stacks with `auto_tagging_enabled=True` on all 6 campaigns — this is why GA4 shows raw numeric campaign IDs instead of names.
- GA4's 4 configured key events are stale from a pre-GHL form system: `form_submit_contact_us`/`form_submit_installation`/`form_submit_schedule_service` haven't fired in 90+ days; the real GHL-form event (`generate_lead`, ~1/4days) was never added as a key event. GA4 "conversions" have been meaningless for months.
- GTM (`GTM-P2MR2T2`, live version 7 confirmed to match audited config) has exactly ONE path to an Ads conversion: GHL form submit → `awct` tag → `Submit lead form - Web`. **No tag fires an Ads conversion off phone clicks, ever, for any campaign.** Ads conversion ID in GTM matches the account's real tracking ID — ruled out wrong-account mismatch.
- Bonus: Meta Pixel ID in the same GTM container is the literal placeholder `123456789` — all Meta tags fire into a fake pixel. Also found two GA4 web streams on the same property with different measurement IDs (`G-XYVZWLC9T8` vs the live `G-CNKY2157HM`) — possible dead legacy install.

**Unresolved, needs Edu's confirmation:** mid-audit, every URL on candsair.com (curl + independent WebFetch, 6/6 attempts) returned a WordPress 500 "critical error" — but Edu opened the site normally with no issue. Response carries `Vary: Cookie`; working theory is a plugin crashes for cookie-less (brand-new) visitors specifically — which would hit paid-ad clickers hardest while looking fine to anyone testing in an already-cookied browser. Asked Edu to test in incognito to confirm/kill this. **Resolved 2026-10-05:** homepage + 3 ad landing pages all return 200 to a cookie-less curl, so the 500 is not happening now (load 2.6-4.8s desktop).

**How to apply:** Don't re-diagnose nonbranded's 0-conversions as a nonbranded-specific problem again — it's a symptom of the account-wide CallRail/GTM/GA4 gaps above.
