2. **`phone_call` conversion action was HIDDEN in Ads (I fixed, live, 2026-08-17):** GA4 event `phone_call` (real CallRail-based connected calls) was firing 315x/28days — the single biggest lead signal on the site, way ahead of `phone_link_click` (71x/28days) — but its imported Ads conversion action (id **7314063586**) sat `status: HIDDEN`, so none of it counted or fed bidding. I flipped `status` → `ENABLED` via `ConversionActionService.mutate_conversion_actions` (this field is mutable via API). Tried also setting `include_in_conversions_metric` in the same call — **rejected as IMMUTABLE_FIELD by the API**; that toggle (and `primary_for_goal`) can only be changed via the Google Ads UI (Conversions summary page → per-action Primary/Secondary column, NOT the per-campaign "Action optimization" section — that's a different, campaign-level setting tied to `campaign_conversion_goal`). Eduardo did this in the UI 2026-08-17 but a re-check via API right after still showed `primary_for_goal: False` / `include_in_conversions_metric: False` — unclear if it didn't save or just hadn't propagated. **Still needs re-verification.**
3. **Bigger, unresolved attribution gap:** broke down `phone_call` vs `phone_link_click` by GA4 channel for the PMax-active window (Jun22-Jul20). 259 of 303 real `phone_call` events (85%) landed in GA4's **"Unassigned"** channel — meaning GA4 itself can't tie most real calls to any session/campaign, so Ads definitely can't attribute them either. `phone_link_click` (the low-value tap) attributes almost perfectly to Cross-network/PMax (645/788). Likely cause: the CallRail number-swap firing the `phone_call` GA4 event drops session/client-ID context (delayed fire, separate iframe, or webhook without gclid), unlike `phone_link_click` which fires in-session. **This is what Eduardo is reworking as of 2026-08-17, ETA "a couple hours."** Until it's fixed, most real call volume will keep landing uncounted regardless of the HIDDEN→ENABLED fix above.
